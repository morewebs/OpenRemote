# Daily project workflow

Date: 2026-11-17

## Intent

Make the existing console practical for someone who works in Claude Code,
Codex and Antigravity all day. The user chose project menus, organization,
search and draft recovery as the first slice. Success means managing a busy
sidebar and switching tasks without losing work.

## Approaches

1. Complete the existing sidebar and composers. Reuse the menu, focus,
   unread and project APIs already present. This is the selected approach:
   useful daily actions without a navigation migration.
2. Replace navigation with full project workspaces, settings and review
   screens. More room for future depth, but delays the basic workflow and
   increases migration risk. Deferred.

## Current evidence

- The project menu exists only on right-click. The visible controls are
  New chat and Remove, so normal pointer and touch use hides useful actions.
- Project order is the daemon's registration order. Only chats can be pinned.
- Sidebar search filters chat titles before grouping. A project-name match
  can expand a project while removing every chat inside it.
- Both composers initialize text with an empty string. Navigating away and
  back loses unsent text. Reproduced in the actual UI with the sample API.
- Baseline: 1,621 console tests pass; production build and capability check pass.
- Existing uncommitted changes include composer UI/CSS and Cloud mesh work.
  Preserve them and add only the changes needed for this slice.

## Behavior

### Project actions

Replace the exposed Remove icon with a three-dot Project actions button.
It opens the same menu as right-click and the keyboard context-menu key.
Keep the quick New chat button. The menu offers:

- New chat here.
- Pin project / Unpin project, with a small pin mark on pinned headings.
- Move up / Move down, within the project's pinned or unpinned group.
- Search chats in this project, with a visible removable project filter.
- Mark all chats as read, using all of the project's active chats, including
  collapsed, paged and waiting chats.
- Open folder on the native desktop; Copy path wherever clipboard is available.
- Collapse / Expand project; Collapse all others.
- Remove project, with the existing second-step confirmation. Its files and
  chats survive. Report failures visibly.

The Projects heading gets an organization menu: manual order, name order,
recent activity, collapse all and expand all. Pinned projects stay first in
all orders. Moving a project switches to manual order, based on the currently
displayed order. With a single project, unavailable movements are disabled.
Project arrangement is local to this console, like existing chat pins and folds.

### Search

Search chat titles, project names and folder paths. A project or folder match
shows all its chats; a chat-title match shows that chat under its project.
Unrelated project headings are hidden. Matching empty projects remain visible.
Search temporarily expands matching projects without overwriting stored folds,
and does not page away matching chats. The explicit project filter composes
with text search and can be cleared independently. Needs you remains visible
regardless of search, preserving the existing approval visibility rule.
Give the search field an accessible name and a clear no-results state.

### Draft recovery

Keep unsent text per composer, using the existing scoped composer keys so
split panes do not share drafts. Restore text on navigation and page reload
within the same window. Use session storage plus an in-memory fallback;
drafts are local and are never sent or synced automatically. Storage failure
must not stop typing. Keep the existing attachment store and async ownership
rules intact.

Clear a draft when a send or queue operation is acknowledged, or when the
person clears the text. Preserve it on refusal or failure. An acknowledgement
must not erase text typed after sending began. Existing delivery-recovery
paths must continue restoring failed first messages. New-chat drafts are
separate from existing-chat drafts. Restoring project/model selections and
durable binary attachments are outside this slice.

## Constraints and non-goals

- Keep React, existing CSS tokens, PickerMenu and ContextMenu; no dependencies.
- Menus work by mouse, keyboard and touch. Preserve focus restoration.
- Do not rename directories or change project identity. Custom project names,
  project instructions, default Apps, worktrees, git review and onboarding
  readiness remain follow-up gaps, not claimed as complete.
- No new Cloud permission, daemon API or native-shell command is needed.
  The file-card addition also forwards Codex's existing fileChange events,
  which the current driver was dropping. Its wire shape was checked against
  the schema generated by the installed Codex 0.167.0 CLI.
- No live paid agent turns, release, deployment or account changes.

## Verification

Behavioral tests cover sorting/pinning/movement, filtered grouping, bulk-read
coverage, corrupt/denied storage, scoped draft isolation and send races.
Use the real UI with sample API data to verify project menus, keyboard Escape,
pin/order reload, search and navigation/reload draft recovery. Re-run the
console suite, production build and capability check. Mock verification does
not establish live CLI behavior or native folder opening.

## Builder decisions

Exact menu grouping, small CSS adjustments and module boundaries are delegated
to the implementer. Use deterministic tie-breakers for sorting; retain unseen
project preferences through the initial loading state. Surface real errors
instead of claiming successful clipboard or project removal operations.

## User-requested addition: file cards

The user supplied Claude Desktop screenshots and explicitly requested its
compact expandable file-change presentation. Render file tools as Created /
Edited plus filename and line counts. Expansion shows a path header and
scrollable, numbered content with green additions/red removals. Read tool
inputs already carried by each App; never read arbitrary files from disk.
Failed writes must read as failed attempts, not successful creation. Keep
unknown tool outputs readable and retain existing review functionality.
