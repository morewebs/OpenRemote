# OpenRemote 0.5.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Publish 0.5.1 with the Android Cloud sign-in fix and smaller ARM64 and ARMv7 APK downloads.

**Architecture:** Preserve atomic identity creation with Android's exclusive rename. Build standalone ARM APKs using Tauri's ABI flavors, retain the existing universal download, and require all three in the release publication gate.

**Tech Stack:** Rust, Tauri, Gradle, GitHub Actions, Node.js.

**Spec:** The user's November 14 request to push and release 0.5.1, including separate ARM64 and ARMv7 APKs.

## Global Constraints

- Preserve existing signing identity and package ID; increase Android versionCode from 14 to 15.
- Include only this task's changes; leave unrelated local mesh changes out of the release.
- Keep version-free download URLs and the universal APK available.

## Review Focus

- A fresh Android sign-in must persist its identity and credentials.
- Concurrent identity creation must not replace another identity.
- ARM64 and ARMv7 APKs must contain only their intended native ABI.
- Missing or unsigned APKs must stop publication.
- The release tag must point to a commit on main with matching app versions.
