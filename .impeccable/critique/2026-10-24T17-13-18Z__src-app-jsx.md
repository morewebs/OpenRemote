## Priority issues

1. [P0] Permission on New chat unmounts the app. NewChat.jsx passes each permission as a whole object into the menu. Settings already maps the word and the label. One click, and the person cannot continue. Map the label the way Settings does, and catch a broken screen so one menu cannot blank the window.
2. [P1] The chat status line cannot be scanned, and Delete sits beside Resume. Show the human permission name, make Stopped and Resume the status, and move Delete off that row.
3. [P1] Small grey text is too faint on every screen. The quiet grey is about 3.5:1. It needs to be dark enough to read at a glance. The same grey is the placeholder, the Model chip, and the captions under Machines, Plugins, and Account.
4. [P1] Home does not look like the rest of the tool. The purple glow exists only there. "Using API Key" and "Sign in" sit side by side. Drop the glow, and make the sign-in line one sentence.
5. [P1] Plugins, Automations, and Settings feel like three products. One button shape, and empty states that name the control that fills them.

## What is working

Settings is a finished tool surface: search, groups, and a clear Daemon row. Harness marks repeat in the sidebar, the menu, and the composer. Keyboard focus draws an amber ring where it was tested.

## Detector

Live scans of New chat, Plugins, Automations, Machines, Account, and one chat all found the same faint grey. Inter and Geist Mono were flagged as overused; the design contract chooses them, so that is not a defect to fix. A pulsing green dot was flagged on a chat; the contract uses that dot for a live run, and reduced motion already stops it. An empty image in the in-app browser is filled when a page is shown, so the static warning is not a broken picture. Plugins skips a heading level. That one is real and small.
